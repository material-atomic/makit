## Request latency (HTTP, end to end)

(CF-Connecting-IP through a trusted proxy). Every makit decision runs the full policy and writes a request
snapshot to disk. "Added" is the difference with the same path without makit. Attack traffic is XSS,
secret probes, SQL injection, Log4Shell and path traversal: makit answers 403 itself and bans the IPs.

## Reading these numbers

- Docker on macOS or Windows adds a virtual machine and its network to every hop: absolute latencies there are
  higher than on a Linux server, and tail latencies (p99, p99.9) vary from one run to the next — run twice before
  drawing conclusions from them.
- The app answers a fixed page, so the runs measure the proxy path, not an application.
- Run it on your own server (`benchmark/run.sh`) and open a pull request with the file from `benchmark/results/`
  to add your machine to the comparison.

## Notes on this run

- A GitHub-hosted runner: 4 shared vCPUs carry the load generator (32 connections), Caddy, Envoy, the app and makit
  at once. A decision costs 9 µs here and a whole `/check` 28 µs, yet ask mode adds ~3 ms at the median: most of
  that is requests waiting for a CPU, not makit working. Run the load generator on another machine to measure what
  makit alone adds; on an 8-core Apple M1 Pro (see the 2026-10-02 report) Caddy ask mode added 1.1 ms.
- The version line says 0.5.0 (the VERSION file) — the code is v0.6 in progress, commit `6fb9199`.
- New in this run: Envoy asking makit through ext_authz, the setup Envoy Gateway and Istio configure.
